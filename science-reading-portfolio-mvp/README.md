# 과학 독서·논술 포트폴리오 — Stage 1 정적 MVP

성취기준 기반 과학 독서·논술 포트폴리오 웹앱의 **Stage 1 정적 MVP**입니다.
빌드 도구·서버·로그인 없이 브라우저에서 바로 동작하며, 모든 데이터는 이 브라우저의
`localStorage`에만 저장됩니다.

- 과목: 통합과학2
- 성취기준: `[10통과2-01-02]` — 변이·자연선택·진화·생물다양성
- 모듈: *생명체의 구조는 '필요해서 생긴 것'인가, '선택되어 남은 것'인가?*

## 파일 구성 (Stage 2 모듈 분리)

| 파일 | 역할 |
|------|------|
| `index.html` | 앱 구조(헤더/학생 화면/교사 대시보드/리뷰 패널) + 스크립트 로드 순서 |
| `styles.css` | 카드형 UI, 표, 대시보드 스타일 |
| `data/students.js` | 학생 익명 ID 목록 |
| `data/activities.js` | 활동 8종 + B1 자료 해석용 표 |
| `data/rubric.js` | 루브릭 6기준 |
| `data/misconceptions.js` | 오개념 태그 + 참고 피드백 문구 |
| `services/storage.js` | localStorage 저장·불러오기 (artifact/review) |
| `utils/metrics.js` | 진행률·제출률·오개념 빈도·평균 점수 등 지표 계산 |
| `app.js` | UI 렌더링·이벤트·JSON/CSV 내보내기 |
| `README.md` | 실행 방법과 기능 설명 |
| `ROADMAP.md` | Stage 2·3 확장 계획 |

모든 모듈은 전역 네임스페이스 `window.SRP` 하나에 붙습니다. 빌드 도구·ES module
import 없이 `<script>` 태그를 **데이터 → 저장 → 지표 → 앱** 순서로 불러오므로
`index.html`을 더블클릭(`file://`)해도 그대로 동작합니다.

## 배포판: `standalone.html` (단일 파일 · 교사 저작)

`standalone.html`은 **한 파일로 완결된 배포용 앱**입니다. 모듈 파일 분리 버전과 달리
CSS·JS가 모두 인라인되어 있고, **교사가 임의의 책·성취기준·활동·루브릭·오개념을 직접
저작**할 수 있는 '단원 설정' 화면이 추가되어 있습니다. (생물학/진화는 시작용 예시 템플릿)

- 학생 / 교사 대시보드 / 단원 설정 3개 화면, 라이트·다크 테마 자동 대응
- 더블클릭으로 바로 실행되며, 별도 배포 없이 정적 호스팅(GitHub Pages 등)에 그대로 올릴 수 있습니다.
- 라이브 배포본(Claude Artifact): 세션에서 공유된 링크로 바로 사용·공유 가능.

## 실행 방법 (모듈 분리 버전)

1. 이 폴더의 `index.html`을 브라우저에서 엽니다(더블클릭 또는 드래그).
2. 별도의 설치·서버·인터넷 연결이 필요 없습니다.
3. (선택) 로컬 서버로 열려면:
   ```bash
   cd science-reading-portfolio-mvp
   python3 -m http.server 8000
   # http://localhost:8000 접속
   ```

## 사용 흐름

### 학생 화면
- 상단에서 **학생 익명 ID**(S-001 ~ S-005)를 선택합니다.
- 활동 카드(A1·A2·B1·B2·B3·C1·D1·E1)에 답을 작성합니다.
- 입력하는 즉시 자동 저장되며, 새로고침 후에도 유지됩니다.
- B1(자료 해석)에는 세대별 형질 빈도 변화 표가 함께 제시됩니다.

### 교사 대시보드
- 상단 **교사 대시보드** 버튼으로 전환합니다.
- 지표 카드: 응답 채움률·빈칸률·논술(B2) 제출률·수정본(B3) 제출률·리뷰 수·피드백 입력률.
- 학생별 진행 현황 표: 활동별 제출 여부(●/·)와 진행률.
- 오개념 빈도: 저장된 리뷰의 오개념 태그 집계.
- **답안 검토·채점**: 학생·활동을 골라 불러온 뒤
  - 기준별 1~4점 루브릭 채점
  - 오개념 태그 선택(선택 시 참고 피드백 문구 표시 — 교사 판단 보조용)
  - 교사 피드백 입력 후 저장.
- **JSON / CSV 내보내기**로 전체 데이터를 파일로 저장합니다.

## 데이터 저장 구조

`localStorage` 키 `srp-mvp-v1`에 아래 형태로 저장됩니다.

```json
{
  "currentStudentId": "S-001",
  "artifacts": { "S-001::B2": { "studentId": "S-001", "activityId": "B2", "content": "...", "stage": "initial", "updatedAt": "..." } },
  "reviews":   { "review::S-001::B2": { "studentId": "S-001", "activityId": "B2", "scores": {}, "misconceptionIds": [], "feedback": "...", "updatedAt": "..." } }
}
```

- 산출물 키: `${studentId}::${activityId}`
- 리뷰 키: `review::${studentId}::${activityId}`

이 구조는 Stage 3에서 Supabase 테이블로 그대로 옮길 수 있도록 설계되었습니다.

## 설계 원칙 (지킨 것 / 넣지 않은 것)

**지킨 것**
- 성취기준 → 활동 → 산출물 → 루브릭 → 피드백 → 포트폴리오 증거 흐름
- 익명 학생 ID만 사용
- 교사가 최종 평가자 (AI는 점수·세특 문장을 확정하지 않음)

**넣지 않은 것 (Stage 1 금지 사항)**
- 로그인 / 회원가입
- 서버 DB / 외부 API 호출
- AI 자동채점 / AI 자동 피드백 / 세특 자동 작성
- 학생 실명·학번·민감정보 저장
- 실제 도서 원문 발췌문 하드코딩

## 데이터 초기화

브라우저 개발자 도구 콘솔에서:
```js
localStorage.removeItem('srp-mvp-v1'); location.reload();
```
