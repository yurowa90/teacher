# 과학 독서·논술 포트폴리오 웹앱 Stage 1.1 QC 및 수정 계획

## 0. 검토 개요

본 문서는 `science-reading-portfolio` 웹앱의 현재 구현 상태를 검토하고, 다음 개발 단계에서 유지할 부분, 개선·수정할 부분, 추가 제작할 부분을 정리한 QC 문서이다.

현재 업로드된 파일 기준 검토 대상은 다음 4개이다.

```text
index.html
styles.css
app.js
README.md
```

현재 구현은 Stage 1.1 Static Bundled MVP로 판정한다.

이유:

- index.html은 학생 화면과 교사 대시보드를 구분한다.
- styles.css는 카드형 활동지, 대시보드, 표, 리뷰 패널 스타일을 제공한다.
- app.js는 학생 데이터, 활동 데이터, 자료 해석 표, 루브릭, 오개념 태그, localStorage 저장, 지표 계산, UI 렌더링, JSON/CSV 내보내기를 모두 포함한다.
- README.md는 기능 설명은 풍부하지만 실제 파일 구조와 일부 불일치한다.

## 2. 현재 유지해야 할 부분

### 2-1. 제품 구조

현재 제품 방향은 유지한다.

학생 활동 작성
→ 자동 저장
→ 교사 대시보드 확인
→ 루브릭 채점
→ 오개념 태그
→ 피드백 입력
→ JSON/CSV 내보내기

이 구조는 성취기준 기반 독서·논술 포트폴리오 웹앱의 MVP로 적절하다.

유지 사유

| 유지 항목 | 이유 |
|-----------|------|
| 학생 화면 / 교사 화면 분리 | 사용자 역할이 명확함 |
| 익명 학생 ID | 개인정보 최소화 원칙에 적합 |
| A1~E1 활동 구조 | 개념 이해 → 논술 → 탐구 → AI 비판 → 성찰 흐름 반영 |
| localStorage 저장 | Stage 1 정적 MVP에 적합 |
| 교사 대시보드 | 제품 핵심 가치인 기록 누적을 보여줌 |
| 루브릭 기준별 점수 | 수행평가·논술형 평가로 확장 가능 |
| 오개념 태그 | 목적론, 개체 변화 등 핵심 오개념 관리에 적합 |
| 피드백 저장 | 초안-수정본 흐름으로 확장 가능 |
| JSON/CSV 내보내기 | 이후 QC·분석·백업에 필요 |

### 2-2. 현재 유지할 데이터 구조

현재 artifactKey, reviewKey 구조는 유지한다.

```text
artifactKey = `${studentId}::${activityId}`
reviewKey = `review::${studentId}::${activityId}`
```

유지 사유

| 구조 | 이유 |
|------|------|
| studentId::activityId | 학생별·활동별 산출물 구분이 명확함 |
| review::studentId::activityId | 교사 리뷰를 산출물과 연결 가능 |
| artifacts 객체 | 학생 응답 저장에 적합 |
| reviews 객체 | 루브릭·오개념·피드백 저장에 적합 |
| currentStudentId | 학생 화면 전환에 필요 |

이 구조는 Stage 3에서 Supabase 테이블로 이동하기에도 적절하다.

### 3-3. 학생 화면 상단 핵심 개념 카드 추가

현재 문제

학생은 바로 A1 활동에 진입한다.
문해력 약한 학생은 변이, 자연선택, 진화, 개체군 개념을 모른 채 작성할 수 있다.

추가할 카드

학생 화면 상단에 다음 카드를 렌더링한다.

오늘의 핵심 개념

- 변이: 같은 종 안에서 나타나는 형질 차이
- 자연선택: 환경에 유리한 형질을 가진 개체가 더 많이 생존·번식하여 그 형질이 더 많이 남는 과정
- 진화: 개체군의 형질 빈도가 세대를 거쳐 변화하는 과정
- 개체군: 같은 지역에 사는 같은 종의 무리
- 생물다양성: 유전적 다양성, 종 다양성, 생태계 다양성을 포함하는 생물의 다양성
- 목적론: “필요해서 생겼다”처럼 어떤 구조가 목적을 위해 직접 생겼다고 보는 설명

기대 효과

| 효과 | 설명 |
|------|------|
| A1 진입 장벽 감소 | 학생이 핵심어를 보고 작성 가능 |
| 오개념 예방 | 목적론 개념을 사전에 제시 |
| 문해력 비계 강화 | 활동 전 선행 조직자 역할 |
| 수업 실행성 향상 | 교사 설명 부담 감소 |

### 3-4. B2 논술 체크리스트 추가

현재 문제

B2 프롬프트는 좋지만, 학생이 조건을 빠뜨릴 가능성이 크다.

추가할 체크리스트

B2 활동 카드 안에 다음 체크리스트를 표시한다.

답안 제출 전 확인

- □ 변이를 설명했다.
- □ 자연선택을 설명했다.
- □ 개체가 스스로 변한 것이 아니라고 썼다.
- □ 개체군의 형질 빈도 변화라고 썼다.
- □ 자료 또는 발췌문 근거를 사용했다.

기대 효과

| 효과 | 설명 |
|------|------|
| 논술 조건 충족률 증가 | 학생이 필수 요소를 확인 |
| 채점 일관성 증가 | 루브릭 기준과 활동 조건 연결 |
| 피드백 부담 감소 | 조건 누락 답안 감소 |
| B3 수정본 품질 향상 | 수정 방향이 명확해짐 |

### 3-5. 오개념 피드백 문구 삽입 버튼 추가

현재 문제

현재 오개념 태그를 선택하면 참고 피드백 문구가 표시된다.
그러나 교사가 피드백 입력란에 직접 복사해야 한다.

개선 기능

리뷰 패널에 버튼을 추가한다.

[선택한 오개념 피드백 문구를 피드백 입력란에 추가]

동작

1. 교사가 오개념 태그를 선택한다.
2. 참고 피드백 문구가 생성된다.
3. 버튼을 누르면 선택된 오개념 피드백 문구가 피드백 textarea에 추가된다.
4. 교사는 문구를 수정한 뒤 저장한다.

주의

자동 확정이 아니라 교사 판단 보조로만 작동해야 한다.

### 3-6. 데이터 초기화 버튼 추가

현재 문제

README에는 콘솔에서 초기화하는 방법만 있다.

```js
localStorage.removeItem('srp-mvp-v1'); location.reload();
```

교사가 쓰기에는 불편하다.

추가 기능

교사 대시보드 하단에 다음 버튼을 추가한다.

[JSON 백업 후 전체 데이터 초기화]

동작

1. 버튼 클릭
2. confirm 표시

현재 브라우저에 저장된 모든 학생 응답과 교사 리뷰가 삭제됩니다.
먼저 JSON 내보내기로 백업했는지 확인하십시오.
정말 초기화하시겠습니까?

3. 확인 시 실행

```js
localStorage.removeItem('srp-mvp-v1');
location.reload();
```

주의

초기화 버튼은 강한 색상 또는 경고 영역에 배치한다.

## 8. 최종 결론

현재 구현은 좋은 Stage 1 MVP이다.
핵심 기능은 이미 구현되어 있으므로 방향을 바꾸거나 폐기할 필요는 없다.

다만 다음 5개는 반드시 수정해야 한다.

1. README와 실제 파일 구조 정합성 수정
2. 학생 화면 핵심 개념 카드 추가
3. B2 논술 체크리스트 추가
4. 오개념 피드백 문구 삽입 버튼 추가
5. 데이터 초기화 버튼 추가

이 5개가 반영되면 현재 버전은 Stage 1.2 UX Stabilization으로 볼 수 있다.
그 다음에야 data/, services/, utils/로 분리하는 Stage 2 Modular Refactor로 넘어가는 것이 적절하다.
